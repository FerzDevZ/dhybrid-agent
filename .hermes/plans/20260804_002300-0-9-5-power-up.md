# Rilis 0.9.5 — Agent Power-up: Observability, State Persistence & Unified LLM Routing

> **For Hermes:** gunakan subagent-driven-development skill untuk mengerjakan plan ini task-by-task. Fresh delegate_task per task, dua stage review (spec compliance → code quality). TDD ketat.

**Goal:** Elevasi dhybrid agent dari "token-efficient CLI" ke "agen AI modular tingkat lanjut" — dengan observability (token/cost/latency metrics), state persistence (session checkpoint via SQLite, bukan memori), dan LLM routing terpusat (litellm sebagai jalur utama, bukan opsional). Fokus: make agent lebih *observable, stateful, dan multi-provider*.

**Architecture:** Ekstrak `litellm_client.py` jadi provider utama (ganti langsung httpx di providers.py untuk non-streaming), tambah `efficiency/metrics.py` (prometheus-style counters tanpa dependensi berat), checkpoint session state ke SQLite via `SessionContext` yang persisten, gunakan `aiofiles` untuk semua I/O debug/skill dump (non-blocking), dan integrasikan `rich` di `repl.py` untuk progress bar + spinner.

**Tech Stack:** Python 3.12, litellm (routing), tiktoken (accurate token), rich (UI), prometheus-style metrics (builtin counters, no external server), SQLite (checkpoint), aiofiles (async I/O).

## Risiko & Tradeoffs

- **Tradeoff: litellm sebagai jalur utama** — meningkatkan dependency berat (+50 paket langsung). Solusi: tetap opsional (provider=="litellm"), default tetap httpx minimal.
- **Risiko: prometheus_client** — tambah koneksi jaringan. Solusi: counters lokal di memori, /metrics endpoint optional.
- **Risiko: redis dependency** — tidak dipaksakan; fokus SQLite checkpoint dulu (bisa migrasi ke redis nanti).
- **YAGNI check:** semua paket ditambahkan hanya bila dipakai Task di atas — tidak ada "flexibility future."
