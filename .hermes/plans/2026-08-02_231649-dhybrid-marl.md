# dhybrid-agent — Model-Agnostic Reasoning Layer (MARL) Implementation Plan

> **Untuk Hermes:** gunakan skill `subagent-driven-development` untuk mengimplementasikan plan ini task-by-task.

**Goal:** Membuat KUALITAS NALAR merata di SEMUA model — model murah/gratis (zen) menghasilkan kualitas kerja setara model premium. Kualitas datang dari arsitektur agent, bukan dari modelnya ("masa harus mde?" → tidak, cukup agent-nya yang cerdas).

**Architecture:** Lapisan "Reasoning Layer" di sekitar loop ReAct yang ada: (1) heuristik kualitas output → auto-escalation antar preset, (2) verifier penyelesaian tugas (cek file/test nyata), (3) few-shot contoh format tool di system prompt, (4) scoreboard kualitas model → routing otomatis ke preset terbaik yang tersedia.

**Tech Stack:** Python 3.12 stdlib + yang sudah ada (httpx, pyyaml). TANPA dependensi baru. Semua heuristik murni (tanpa LLM) supaya murah.

## 2. Phase 1 — Heuristik Kualitas Output + Auto-Escalation (tanpa LLM, murah)

**Objective:** Ukur kualitas jawaban final secara heuristik; bila jelek → ulangi dengan preset model berikutnya (escalation chain). Berlaku untuk SEMUA model → output merata.

**Files:**
- Create: `src/dhybrid/agent/quality.py`
- Modify: `src/dhybrid/agent/loop.py` (escalation), `src/dhybrid/session/context.py` (escalation chain)
- Test: `tests/unit/test_quality.py`, `tests/e2e/test_agent_loop.py`

### Task Q1: Skor kualitas output (murni, 0-100)

```python
# src/dhybrid/agent/quality.py
import re

REFUSAL_HINTS = (
    "tidak bisa", "tidak dapat", "tidak punya akses", "cannot", "can't",
    "tidak memiliki akses", "belum bisa", "tidak tersedia di sini",
)
QUESTION_HINTS = ("?", "mau yang mana", "pilih", "apakah", "bagaimana sebaiknya")

def score_output(text: str, *, is_build: bool = False, tools_used: int = 0,
                 files_created: int = 0, tests_passed: bool | None = None) -> int:
    """Skor kualitas jawaban final. 0-100. Dipakai untuk keputusan escalate."""
    t = (text or "").strip()
    score = 50
    if not t:
        return 0                      # diam → gagal total
    if any(h in t.lower() for h in REFUSAL_HINTS):
        score -= 40                   # menolak kerja
    if is_build and re.search(r"\?\s*$", t):
        score -= 30                   # balik bertanya saat diminta buat
    if is_build and files_created == 0:
        score -= 25                   # diminta buat tapi tidak ada file
    if tests_passed is True:
        score += 20
    if len(t) > 300:
        score += 10                   # jawaban substansial
    elif len(t) < 60 and is_build:
        score -= 15                   # terlalu pendek untuk tugas membangun
    return max(0, min(100, score))
```

**Task Q1.1:** tulis test gagal → implement → PASS:
- `score_output("") == 0`
- `score_output("Saya tidak bisa melakukan itu") < 40`
- build request tanpa file → rendah; dengan file + test → tinggi.

### Task Q2: Escalation chain di loop

- `Context` menyediakan `escalation_chain()`: daftar preset dari config `model.chain` (default: `[model aktif, opencode-zen-big, openai-fast, anthropic-big]` — yang key-nya tersedia saja).
- Di `loop.run()`: setelah jawaban final, hitung `score = score_output(...)` (dengan info `_used_mutating_tool`, jumlah tool, file yang dibuat via tool_count).
- Bila `score < 60` DAN masih ada preset berikutnya di chain → pindah client, push pesan: `"[sistem] Jawabanmu dianggap kurang memadai (skor X/100). Lanjutkan dengan kualitas lebih tinggi: selesaikan tugasnya, jangan bertanya/menolak."` → lanjut loop (max 1 escalation per run, sudah ada batas step).
- Skor akhir disimpan di `LoopResult.quality_score` dan ditampilkan di `[done]` line.

**Task Q2.1-2.4:** TDD → test: ScriptedClient yang menjawab "Saya tidak bisa" → escalation memakai client kedua (calls berpindah); skor tercatat.

### Task Q3: Config chain

- `config/default.yaml`: `model.chain: []` (kosong = nonaktif? atau default `["opencode-zen-big"]`). Rekomendasi default: chain hanya berisi preset yang KEY-nya terisi — dihitung runtime dari env.

# src/dhybrid/agent/verify.py
from pathlib import Path

def count_created_files(cwd: str, before: set[str], after: set[str]) -> int:
    return len(after - before)

def verify_build(cwd: str, tool_events: list[dict]) -> dict:
    """Bukti nyata: file dibuat, test dijalankan, git diff."""
    return {
        "files_created": ...,
        "tests_ran": any(e["name"] == "run_tests" or "pytest" in str(e.get("args", "")) for e in tool_events),

        "git_changed": ...,

- Setelah loop: `verify_build(cwd, events)` → masukkan ke skor kualitas (Q1) DAN tampilkan baris `[verifikasi: 3 file dibuat, test ✓]` di [done].
- Ini memberi user BUKTI, bukan klaim — dan memberi loop data untuk escalate.

## 8. Metrik Sukses (definisi selesai)

- **P1:** task yang sama di `deepseek-v4-flash-free` menghasilkan kualitas output yang SETARA dengan model premium (skor ≥ 70) — karena escalation otomatis.
- **P2:** `[done]` selalu menyertakan `[verifikasi: N file, test ✓/✗]` untuk task build.
- **P3:** 100% tool call model lemah dikenali (format benar/fallback).
- **P4:** `dhybrid doctor` menampilkan peringkat; default `auto` memakai preset terbaik yang tersedia.

## 9. Risiko & Tradeoff

- **Escalation biaya:** chain ke model premium memakai key user → hanya bila skor < 60 (jarang untuk tugas kecil). Config `model.chain` bisa dikosongkan (nonaktif).
- **Verifier salah deteksi:** file dibuat di luar cwd (model menulis /home/...) → verifier hanya hitung file DI BAWAH cwd.
- **Scoreboard bias:** skor dari 3 task kecil ≠ jaminan umum → label "sementara, makin dipakai makin akurat".
- **Few-shot menambah token:** +150 token system prompt sekali per sesi — ter-cache (prompt caching) → dampak biaya ≈ 0.
